# Ruach decision log

**Read this file first when picking up the project.** Before it, read the Ruach Master Blueprint in the Claude project files. The blueprint says what to build; this file says what was decided while building, what is finished, and what is next.

## How to use this log

- Append a new entry at the bottom of "Decisions" whenever a choice is made that the blueprint does not already settle, or whenever a build fact overrides the blueprint. Number entries D-001, D-002 and so on. Never rewrite an old entry; add a new one that supersedes it.
- Update the "Batch status" table at the end of every batch, in the same commit as the batch.
- Update "Open items" when something is requested from the owner or resolved.
- Never write secrets (tokens, passwords, keystore contents) into this file or anywhere in the repo.
- Delivery flow for every batch: commit to `ci-analyser`, read the `check` workflow result and logs through the GitHub API, fix on that branch until green, then push the same commit to `main`. Commit messages read `batch-id: purpose`.

### D-003: check workflow tolerates an app-less repo
Until `app/pubspec.yaml` exists (p1b), `check.yml` runs only the repository-level checks and skips the Flutter steps, so p1a can go green on its own.

## Unreviewed languages

None translated yet. Non-English languages arrive at p6b and are listed here as unreviewed until a native speaker confirms them.

### D-007: no Material package
Flutter 3.50 moved the Material widgets into a separate package, `material_ui`, and the generated template depended on it. Ruach draws its own components on the widgets layer (blueprint section 6), so the dependency, `cupertino_icons` and the Material icon font (`uses-material-design: false`) were removed. Code imports `package:flutter/widgets.dart`.

### D-008: portrait only
The blueprint did not fix screen orientation. Ruach is portrait only on Android (`screenOrientation="portrait"`) and on iPhone and iPad (`UISupportedInterfaceOrientations`), because the control layout, HUD and one-handed option are designed for a portrait phone. Reversible by editing those two settings and the layouts.

### D-009: draft iOS privacy manifest, not yet wired
`app/ios/Runner/PrivacyInfo.xcprivacy` declares only the required-reason APIs the app is known to use (user defaults CA92.1, file timestamp C617.1). The tracking flag, tracking domains and collected data types depend on the final plugin list, so they are completed at p7b. The file also has to be added to the Runner target in `project.pbxproj`, which needs an iOS build to verify, so that wiring is also done at p7b. Until then it does nothing.

### D-010: Android keeps the Kotlin build files
The generated project uses `build.gradle.kts`, not the Groovy `build.gradle` the blueprint named. Every blueprint reference to `build.gradle` means `app/android/app/build.gradle.kts`. Release signing reads `android/key.properties`, which the release workflow writes on the runner from the four repository secrets and which is git-ignored. Without that file the build uses the debug key, and `build_and_deploy.yml` (p7b) must fail a release build if the file is missing.

### D-011: iOS ad and tracking entries deferred
`GADApplicationIdentifier` and `SKAdNetworkItems` are not in `Info.plist` yet because the iOS sample app ID and the full identifier list are not confirmed (D-006). They are added at p2f when the ads plugin goes in, and checked again at p7b before the iOS build. The tracking prompt text (`NSUserTrackingUsageDescription`) is written in English now; its translations go in `InfoPlist.strings` files at p6b.

### D-012: pubspec.lock removed for now

The sandbox cannot run `flutter pub get`, so that needs a small manual workflow that runs `flutter pub get` on a runner and commits the lock; build it at p1d.

### D-012 update: lockfile and packages are handled by a runner workflow (resolved)
The manual `.github/workflows/pub_deps.yml` adds packages (`flutter pub add`), refreshes `app/pubspec.lock`, commits both, and can print a package's version, library tree and source so its API is read before code is written against it. Run it from `ci-analyser`; it commits to that branch, so pull before the next push (`git pull --rebase origin ci-analyser`).

### D-015: icon set is Phosphor, Bold weight, behind one wrapper (superseded by D-021)
`phosphor_flutter` 2.1.0 (MIT, Copyright (c) 2020-2021 Phosphor Icons). Only the Bold weight is used: its stroke is about 2.25 px at 24 px, matching the 2.0 to 2.25 rule. `theme/icons.dart` (`AppIcons`) is the single alias file mapping meanings to symbols, and `theme/app_icon.dart` (`AppIcon`) is the single widget that draws an icon; the blueprint's one-wrapper-plus-one-alias-file is these two files. Rules that must hold:
- Do not use the package's `PhosphorIcon` widget. Its library imports `package:flutter/material.dart`, which Flutter 3.50.0 still ships but marks deprecated in favour of `material_ui`. The package therefore compiles only while the SDK ships that file. This is one more reason the Flutter version is pinned (D-002); re-check on every Flutter upgrade.
- `AppIcon` never builds a new `IconData`, because a non-constant `IconData` makes release builds fail the icon-trimming step.
- The package marks every icon to mirror in right-to-left text. `AppIcon` draws icons under a fixed left-to-right direction unless `mirrorInRtl` is true, which only direction icons (back, forward) use.
- The package bundles six weight fonts. Install-size impact is measured at p7b; if it is too large, only the Bold font file will be kept.

### D-016: typeface is Barlow
One bundled Latin face: Barlow Regular 400, Medium 500, SemiBold 600 and Bold 700, taken from the google/fonts repository (`ofl/barlow`), SIL Open Font License 1.1, copyright 2017 The Barlow Project Authors. All four files were checked for tabular figures (`tnum`) and for the accented Latin characters Spanish, French, German and Portuguese need. Notice: `app/assets/notices/barlow-OFL.txt`. Arabic, Hebrew, Hindi, Japanese, Korean and Chinese use the platform's system fonts, as the blueprint says. Display text (brand, position, lap time) uses tabular figures so digits do not jitter.

### D-017: domain colour tokens
Defined and contrast-checked by `test/theme/tokens_test.dart`: `starFill` (light #B8750A, dark #F5B94A), `giftFill` (#1B6B3A, #5FD08B), `ruachMeter` a cool teal because the Ruach meter must stand apart from the warm interface (#0E6E8A, #6CCBE8), `verseCardSurface` parchment (#FBF3E0, #2A2318). They must reach 3:1 as graphics against the two main surfaces, and the three text colours must reach 4.5:1 on `verseCardSurface`. Race-world colours (`trackAsphalt`, `trackSand`, `trackStone`) are not themed and carry no text. The test recomputes every pair on each push, so a colour edit that fails contrast fails the build.

### D-018: race numbers
Lap times, positions, laps and counts use Western digits and fixed separators in every language (`utils/formatters.dart`). Hundredths are truncated, never rounded, so a shown time never beats the real one.

### D-019: error handling split
`AppErrorHandler` treats errors raised in the Flutter framework (build and layout) as recoverable, logs them, and carries on. Errors that escape every handler (uncaught asynchronous errors) are fatal and publish on `AppErrorHandler.fatal`, which the app root (p6a) turns into the full-screen fallback with Retry and an email-the-log link. The reporter is injected; the real log writer arrives with `platform/log_service.dart` at p2e.

### D-020: Phosphor licence text (resolved by D-021)
`assets/notices/phosphor-MIT.txt` has the copyright line and the opening of the licence checked against the installed package. The rest is the standard MIT licence wording, written from the standard text rather than copied byte for byte. To make it exact, copy `LICENSE` from the installed package (`pub_deps.yml` with `inspect` prints it).

### D-021: Phosphor Bold font bundled directly; no icon package (supersedes D-015 and D-020)
The first p1d build failed because `phosphor_flutter` 2.1.0 does not compile on Flutter 3.50.0: the SDK made `IconData` a `final class`, and the package extends it. Rather than wait for a fixed release, the app bundles the Phosphor Bold font itself and declares each symbol as a constant `IconData` in `theme/icons.dart`.
- Source: `phosphor-icons/phosphor-flutter` at tag v2.1.0, commit 0646a965ca3d8de8951f6fdd980f38320229f653. The font file is `lib/fonts/Phosphor-Bold.ttf` there (kept as `app/assets/fonts/Phosphor-Bold.ttf`), and the codepoints were read from `lib/src/phosphor_icons_bold.dart` at the same commit by script. All 41 symbols used were confirmed to exist.
- Licence: MIT, Copyright (c) 2020-2021 Phosphor Icons. `assets/notices/phosphor-MIT.txt` is now the licence file copied byte for byte from that commit (this resolves D-020).
- The `phosphor_flutter` dependency is removed, which also removes the deprecated `material.dart` import and the five weight fonts the package would have bundled.
- Direction icons (back, forward) set `matchTextDirection: true` on the icon itself, so they mirror in right-to-left languages and every other icon keeps its shape. `AppIcon` therefore has no mirror flag and no direction wrapper.
- To add an icon: look up its codepoint in the Phosphor Bold table at the commit above, add one `AppIcons` entry, and keep the Phosphor name in the trailing comment.

### D-022: Core models are plain final classes with asserts, no Flutter annotations
Core is pure Dart (no `package:meta`/`@immutable`), so models are `final class` with `const` constructors where all fields are const-friendly. Invariants are `assert`s (debug and test only); data from outside (saved progress, sensors) is forced into range by `clamped`/`fromMap` factories. `Track.validate()` returns a list of problems and the catalog test (p2g) requires it to be empty. `tools/check_layers.dart` runs in check.yml and fails if anything under `app/lib/core` imports Flutter, Flame, `dart:ui`, `dart:io` or a higher layer.
