# Ruach decision log

**Read this file first when picking up the project.** Before it, read the Ruach Master Blueprint in the Claude project files. The blueprint says what to build; this file says what was decided while building, what is finished, and what is next.

## How to use this log

- Append a new entry at the bottom of "Decisions" whenever a choice is made that the blueprint does not already settle, or whenever a build fact overrides the blueprint. Number entries D-001, D-002 and so on. Never rewrite an old entry; add a new one that supersedes it.
- Update the "Batch status" table at the end of every batch, in the same commit as the batch.
- Update "Open items" when something is requested from the owner or resolved.
- Never write secrets (tokens, passwords, keystore contents) into this file or anywhere in the repo.
- Delivery flow for every batch: commit to `ci-analyser`, read the `check` workflow result and logs through the GitHub API, fix on that branch until green, then push the same commit to `main`. Commit messages read `batch-id: purpose`.

### D-015: icon set is Phosphor, Bold weight, behind one wrapper (superseded by D-021)
`phosphor_flutter` 2.1.0 (MIT, Copyright (c) 2020-2021 Phosphor Icons). Only the Bold weight is used: its stroke is about 2.25 px at 24 px, matching the 2.0 to 2.25 rule. `theme/icons.dart` (`AppIcons`) is the single alias file mapping meanings to symbols, and `theme/app_icon.dart` (`AppIcon`) is the single widget that draws an icon; the blueprint's one-wrapper-plus-one-alias-file is these two files. ### D-022: Core models are plain final classes with asserts, no Flutter annotations
Core is pure Dart (no `package:meta`/`@immutable`), so models are `final class` with `const` constructors where all fields are const-friendly. Invariants are `assert`s (debug and test only); data from outside (saved progress, sensors) is forced into range by `clamped`/`fromMap` factories. `Track.validate()` returns a list of problems and the catalog test (p2g) requires it to be empty. `tools/check_layers.dart` runs in check.yml and fails if anything under `app/lib/core` imports Flutter, Flame, `dart:ui`, `dart:io` or a higher layer.

### D-023: Saved data is read tolerantly; progress and settings carry their own JSON
`Progress` and `Settings` have `toJson`/`fromJson` in the model files, built on `core/models/json_read.dart`. Reading never throws: a missing key, a wrong type or an out-of-range number becomes the default or is clamped, and unknown keys are ignored. Writing sorts keys and set members so the same data always encodes to the same text (needed for tests and for backup comparison). `progress_codec.dart` (p2d) adds the version check, migrations, atomic write and backup recovery on top; a schema newer than the app is kept as read and never overwritten there.
- Stars are best-per-track (0 to 3); a track is cleared at one star or more. Gifts are stored as earned and spent totals, and the balance is their difference.
- Daily Run dates are `yyyy-MM-dd` strings supplied by the caller; core never reads the clock.
- Ghosts are base64 text in progress; reader bookmarks and highlights have fields now so p8 needs no schema change.
- `AdState.canRequestAds` is only ever set from UMP's answer. Banners and interstitials need it and no Remove Ads purchase; rewarded needs only it.

### D-025: Curated verse selection rules
332 verses (quotas from blueprint section 5, plus 6 for the upgrades) are chosen from `candidates.json` in priority order. A verse is only eligible if it has text in all 11 languages and its chapter has the same verse count in every language (one reviewed exception: Acts 28:15). Verses are single verses; verses that start mid-sentence in English were replaced by complete ones. Bundles are `app/assets/verses/<language>.json.gz` (`{schema, language, source, verses:[{ref, moments, text}]}`) written with a fixed gzip timestamp so rebuilding gives identical bytes. A verse can carry several moments but none is currently reused. Rewarded-ad, wording and spiritual-advantage rules still apply to the verse tone: gratitude on wins, steadiness on podiums, gentle comfort after a poor finish.

### D-026: p2b race logic design
- **Added file:** `core/logic/track_geometry.dart` (not in the blueprint list). It turns a `Track` into a dense closed Catmull-Rom polyline and answers "where along the road is this point" (`project`, with a segment hint for speed) and "where is this distance" (`positionAt`, `tangentAt`, `widthAt`, `curvatureAhead`, `surfaceAt`). Lateral offset is positive to the right of travel. `numeric.dart` holds `clampDouble` and `wrapAngle`.
- **Physics:** arcade model at a fixed 60 Hz (`RaceSimulation.dt`). Forward speed follows throttle, brake and a cap set by surface, boost and upgrades; steering is limited by grip (`yaw limit = 13 * grip / speed`); sideways velocity decays at `7 * grip` per second. Drag only applies when coasting. All values are tuning starting points; the balance simulation (p2c) adjusts them.
- **Laps:** `LapTracker` credits only small forward steps (30 m maximum), so cutting across the infield earns nothing and the lap needs the missed distance afterwards. After 120 steps away it re-anchors without credit.
- **Rules:** `RaceSimulation` has a 3-second countdown, the player starts last on a two-wide grid, the race ends when the player finishes or after `(par x laps x 3 + 60)` seconds. Cars far off the road are held at 14 m beyond the edge. Rival input comes from a `CarController` (implemented by the AI in p2b-2). Mode rules (p2c) use `eliminate()`.
- **Clean driving:** on the road and no contact in the last second. It feeds the clean-driving score and fills the Ruach meter (0.075 segment per second, so three segments take 40 s). Slipstream charges after 0.5 s behind a rival within 22 m at 0.25 segment per second; drifting charges at 0.2.
- Determinism: `stateHash()` summarises positions, velocities and laps; tests check two identical races agree.

### D-027: Rival AI (p2b-2)
`AiDriver` (one per rival, built by `AiDriver.forRace(config)` with RNG streams forked from the race seed) follows the centreline with an offset to the inside of the next corner, brakes for corners using `13 x vehicle grip x cornerUse` where cornerUse runs from 0.55 (skill 0) to 0.92 (skill 1), passes cars ahead on the side with room (aggression sets how far), leans towards a car behind when defending (aggression above 0.55), wanders by `(1 - consistency)`, waits `(1 - skill) x 0.35 s` plus up to 0.15 s after the lights, and spends boost on straights. `AiTuning` holds the difficulty pace (0.90, 0.96, 1.00) and the rubber band, capped at plus or minus 4 percent over 150 m. All values are starting points for the p2c balance simulation.

## D-028 (p2c) Modes, upgrades, stars, daily seeds, input strategies
- Star keys: Journey/Quick/Daily use the track id; Time Trial uses `tt:<track>`; Escape Run uses `escape:<track>`. Time Trial and Escape stars feed the Gift pool so 90 Gifts is reachable. Only improvements earn Gifts.
- Unlocks: tracks sequential (a star on the previous track), Now variants after the Then track is cleared; chariots open, cart and modern vehicles open with track 9; Quick/Time Trial after track 1, Escape after track 2, Elimination after track 5, Weekly after a completed Daily.
- Upgrades cost 1..5 Gifts per level (15 per upgrade, 90 for all six).
- Daily/Weekly seeds are pure functions of the civil date (ISO week); streak resets gently with a welcome-back prompt.
- Input strategies (buttons, drag steer, tilt) are pure Dart in core/logic/input_strategy.dart.
- Elimination drops last place per leader lap; Escape Run wall 24 m/s +0.12/s, cap 52.
- race_rules: `eliminate()` ends the race if the player is dropped; public `endRace()`; `LapTracker.forceFinish`. Ids live in catalog_ids.dart.

## D-032 (p2g) Catalogs
- Tracks are recipes (`TrackSpec`: ellipse radii, up to three harmonics, width, surfaces, scenery) that `TrackCatalog` turns into closed centrelines of 48 control points. The outline is star-shaped, so a track can never cross itself. Now variants share the Then geometry, with asphalt, no zones, 10% wider road and `guardrails`/`lamps` scenery (no dust wall).
- Par lap times come from `ParEstimator` (speed profile limited by grip, braking and acceleration, x1.2 slack) for the Journey default vehicle (`VehicleCatalog.journeyDefault`: light chariot on 1 to 8, road cart on 9 to 12, hatch on Today tracks and Now variants).
- Catalog test: every one of the 28 tracks validates, has drivable corners (minimum radius at least 45 m), and is finished by the line-following player within 2.2x par with five AI rivals still moving.
- 12 fictional rivals (invented names and teams) in `RivalCatalog`; name clearance (open item 5) covers them.
- Track-intro and upgrade verses are in `VerseMoments` and checked against all 11 languages. Names of tracks are shown from the language files (p6), not the catalog.

## D-034 (p3b) Feature providers
- `RaceProvider` steps the simulation at a fixed 60 Hz from frame time, at most 8 steps per frame (surplus time is dropped so the game never runs fast afterwards). Stars: position, Time Trial (best lap against par) or Escape Run (metres). `commit()` is idempotent and also stores best lap and best Escape Run distance.
- `ConsentProvider` joins the consent answer with the Remove Ads purchase into `AdState`; a failing consent service leaves ads off.
- `AdProvider` rules: nothing before consent, nothing when the remote switch is off, no interstitial in the first session, none within 3 minutes of the last, none after the first Daily attempt of a day. Remove Ads stops banners and interstitials only; rewarded ads stay the player's choice.
- `DailyProvider`: the first attempt of a day is free; later ones are "extra" (rewarded ad, or free with Remove Ads; the screen decides). Attempts are saved at the start of a race. A lapsed streak reads 0 until the next run. The reminder needs permission first; refused means no change.
- `VerseProvider` records each verse shown as seen; `FlagsProvider` keeps the last good flags when a fetch fails. `AppScope` hands all providers down the tree.

## D-035 (p4a) Components
- All tappable components share `Pressable`: no ripple, a 150 ms fade to 70% (instant under Reduce Motion), a hit area of at least 48 square whatever the visible size, and a spoken label that replaces the inner text when given. `PrimaryButton` also scales to 0.97 (the Motion table); `AppRow` tints its background instead of fading.
- `AppChip` has two tones only (neutral, accent), because those are the pairs the contrast test covers. Add a tone only together with its contrast pair.
- `NavBar` takes the status-bar inset itself, shows the brand or a back button (a back button must have a spoken label), and the title wraps to two lines instead of clipping at large text sizes.
- Tests use `isSemantics` (Flutter 3.50 removed `SemanticsFlag`; `containsSemantics` is deprecated).

## D-036 (p4b) Feature widgets
- `AdSlot` is a plain widget: the screen passes the banner widget (or null) and the height from the ad port. It collapses to zero height with no border when the ad is null, the height is 0, or the keyboard is open. The widget that draws the real banner (it needs the ad plugin) is supplied by the shell at p6a, so `widgets/` stays free of ad plugins.
- Badges, the boost meter, the upgrade tile and the error view take every visible and spoken string from the caller (the language files), including plural forms such as "12 Gifts".
- `BoostMeter` fills from the start side (right in Arabic and Hebrew); the race HUD that hosts it caps its own text scale (p4c).
- `ErrorView` scrolls, so it stays usable at 200% text on a small screen.
